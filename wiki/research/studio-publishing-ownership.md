# Studio publishing ownership

Publication serialization was implemented and verified on 2026-10-16 and now lives in QRK's existing snapshot files. The subsequently approved Image upload ownership change is recorded separately below; its compilation and runtime verification are complete. The other scan candidates were considered and left unchanged.

## Implemented ownership

QRK owns its persisted publication format, including the saved Library content inside it. `PageSnapshotSchema` now declares the complete page/wall shape, and `makePageSnapshot` projects the complete saved page content. Both use Library's existing editable models and field codecs. The former `WallSnapshotSchema` and `makeWallSnapshot` Library files and package exports are removed; no new helper, named type, or forwarding seam replaces them. [Schema](/Users/morgs32/GitHub/qrk.sh/apps/zerospin/src/aggregates/user/snapshots/pageSnapshotSchema.ts), [Projection](/Users/morgs32/GitHub/qrk.sh/apps/zerospin/src/aggregates/user/snapshots/makePageSnapshot.ts), [Library models](/Users/morgs32/GitHub/qrk.sh/apps/library/libraryModule/libraryModule.ts:127), [Library exports](/Users/morgs32/GitHub/qrk.sh/apps/library/package.json).

The relocation preserves stored content shape, field exclusions, ordering, command payloads, model/contract versions, and runtime behavior. All three publishing commands and Studio continue using the same `makePageSnapshot` definition. There is no stored WallSnapshot model. Library's renderer reads live model rows, and its standalone durability uses the existing session backup mechanism. [Renderer](/Users/morgs32/GitHub/qrk.sh/apps/library/lib/BrickWall.tsx), [Standalone session](/Users/morgs32/GitHub/qrk.sh/apps/library/session/createLibraryStandaloneSession.ts).

The keep-Library argument was proximity to its content models. That remains appropriate for field codecs and editing invariants. Publication serialization instead chooses QRK's persisted representation; source inspection found no independent Library consumer of that representation. Folding it into QRK removes the package seam while preserving reuse among its actual callers. Archived Plan 025 records the former split and remains unchanged as historical evidence. [Historical plan](/Users/morgs32/GitHub/qrk.sh/wiki/archive/plans/025-plan-studio-publishing.md).

## Implemented follow-up: host-owned Image uploads

[Plan 027](../archive/plans/027-plan-host-owned-image-uploads.md) changes the existing `ImageUploadEnvironment` service to one operation: `upload(file): Effect.Effect<string, Error>`. The Image module passes its validated file and receives the uploaded image URL. It no longer constructs a request from endpoint, site ID, or authorization fields. The former request helper is removed; the environment's service identity/export and existing runtime context remain. [Environment](/Users/morgs32/GitHub/qrk.sh/apps/library/modules/image/ImageUploadEnvironment.ts), [Image form](/Users/morgs32/GitHub/qrk.sh/apps/library/modules/image/ImageForm.tsx), [Runtime context](/Users/morgs32/GitHub/qrk.sh/apps/library/modules/image/ImageUploadRuntimeContext.ts).

1. Studio's existing EditorLayout supplies the operation and owns fresh Clerk-token acquisition, the configured `/upload` endpoint, multipart file/current-site fields, authorization headers, response parsing, and Effect Schema decoding. Library's standalone layout supplies its anonymous `/image/upload` operation with no site or authorization fields. Both use the existing session runner and forward Effect interruption to `fetch`. No shared HTTP adapter was added because these protocols belong to the two actual hosts. [Studio host](/Users/morgs32/GitHub/qrk.sh/apps/app/app/[username]/site/[siteId]/page/[pageId]/EditorLayout.tsx), [Standalone host](/Users/morgs32/GitHub/qrk.sh/apps/library/app/LibraryLayout.tsx).
2. Image retains file validation, picker/drop behavior, unsaved drafts, pending/error feedback, Save gating, cancellation, and suppression of late results. Success updates only the draft URL; Save persists Image state. Cancel and leaving the form interrupt unfinished work without changing saved state. Completed uploads retain their existing storage lifetime. [Form lifecycle](/Users/morgs32/GitHub/qrk.sh/apps/library/modules/image/ImageForm.tsx).
3. Server authentication, routes, request/response formats, R2 keys, asset serving, Site Settings uploads, and the ordinary module form contract remain unchanged. No dependency, source helper, provider, model/contract version, migration, or reset was introduced. [API routing and authentication](/Users/morgs32/GitHub/qrk.sh/apps/api/Worker.ts:41), [Upload storage](/Users/morgs32/GitHub/qrk.sh/apps/api/handleUpload.ts).
4. This implements the image-protocol candidate from the scan without expanding the earlier publication relocation. Normal compilation and manual verification in both applications passed; the separate Image evidence below records the actual outcomes and an initial development-session interruption.
