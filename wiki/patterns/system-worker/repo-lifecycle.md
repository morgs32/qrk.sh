# Repo schema, activation, and alarms

**Every system Durable Object Repo has one immutable physical schema.** Use `makeFixedDORepo`; it provisions the current schema once, records the bootstrap marker only after initialization succeeds, and performs no schema work on a marked cold activation. `makeMigratableDORepo` is the evolving-schema sibling (ordered SQL migrations replayed on every activation, including after bootstrap); system Repos stay on `makeFixedDORepo` until explicitly switched. Standalone evolving-schema storage repos may use `makeMigratableDORepo` with owner-authored SQL migrations. Do not add schema targets, checked-in SQL histories for fixed system Repos, CLI migration generate/check, or Worker-version routing for schema compatibility. Changed `makeFixedDORepo` schemas require empty storage.

**DO alarms are owned by the common Repo base.** Repos inherit `alarmRegistry` and `alarm()` from `makeDORepo`; do not add private registries, alarm overrides, or per-Repo `alarm/alarm.ts` dispatch wrappers. Queue factories synchronously register their lazy drain Effects. Subscriptions belong to `onDOActivation()`, not alarm registrations. Do not add a Repo alarm hook or DOConfig alarm callback. Registration performs no storage access or delivery. Every alarm runs all registered operations against durable state, independently of in-memory leases, and awaits every outcome before propagating combined failures. Each operation retains responsibility for its own alarm holds and releases.

**DO activation is owned by the common Repo base.** After parsing the physical name, `makeDORepo` runs optional `validateKey({ key })` before database config resolution. Inside the constructor gate, optional `registerRepo({ key, name, schema })` runs before storage access, provisioning, bootstrap, or subscriptions. `makeFixedDORepo` owns system version checks, serializes the executing bundle, and requires matching accepted SystemRepo locks through those callbacks. AggregateChain activation requires the configured `systemId` and validates its physical aggregate ID; registration commits Repo metadata and one `{ aggregateName, aggregateId }` row in SystemRepo's `aggregates` table together. Aggregate-ID lookup and exact membership query that table directly. Registration never creates locks and remains recorded if later initialization fails. SystemRepo's fixed config omits `repoType` and is exempt from self-registration. `makeMigratableDORepo` supplies neither system callback and can be imported from its defining module without application `config`; the common namespace interface is open and consumers declare their own bindings. Override `onDOActivation()` for per-activation preparation after schema/bootstrap and before completing the constructor concurrency block. `ready()` explicitly wakes a Repo. Materializer and actor subscribers catch up and enroll through shared fanout; session subscriptions preserve browser synchronization. Do not hold an execution permit or SQL transaction across subscriber RPCs. Queue drains own alarms and delivery recovery; retain holds before committing pending delivery. Source-bound capabilities validate exact owner identity and retained projection progress.
