# Brick preview lift and tilt

Researched November 12, 2026. The requested effect combines a shadow, a tilt that changes as a Brick moves across its horizontal row, and a tilt that follows the cursor over an individual preview.

## Prior art

- **Motion's Coverflow carousel** turns items on either side of the center in 3D. Its description maps each item's offset from center to `rotateY`, scale, and horizontal position. This is a close reference for a persistent tilt that changes with a card's position in the row. Its example uses the paid Motion+ Carousel, and access to its example source is part of Motion+. [Coverflow example](https://motion.dev/examples/react-carousel-coverflow).
- **Swiper's Coverflow demo** provides another interactive reference for cards that change orientation while moving through a carousel. The effect is one of Swiper's published demos. [Swiper demos](https://swiperjs.com/demos#effect-coverflow).
- **Motion's tilt card** tracks pointer position and uses springs for a card that tilts toward the cursor. Its live demo is available to inspect, while the full tutorial is part of Motion+. [Tilt card example](https://motion.dev/examples/react-tilt-card), [live demo](https://examples.motion.dev/js/tilt-card).
- **Vanilla Tilt** provides an interactive collection of tilt examples, including reversed tilt, glare and reset behavior. Its source measures the target rectangle, normalizes pointer coordinates, clamps them to the element, maps them to bounded rotation, and schedules updates with `requestAnimationFrame`. Its documented options include maximum angle, perspective, scale, easing and reset. [Live examples and options](https://micku7zu.github.io/vanilla-tilt.js/), [implementation](https://github.com/micku7zu/vanilla-tilt.js/blob/master/src/vanilla-tilt.js).
- **Motion's 3D planes** responds to scroll velocity with a wave, and hovering lifts a plane. This is a reference for motion that settles when scrolling stops. Its Gallery component and example are Motion+. [3D planes example](https://motion.dev/examples/react-scroll-velocity-linked-offset).

## Applying the ideas to QRK

The current catalog has independent native horizontal scroll rows, and each preview's width depends on its Brick and breakpoint. A preview has a full-size selection Button and a separate Brick action, and it already tracks visibility and reduced motion for its preview content. [Filmstrip](../../apps/app/app/%5Busername%5D/site/%5BsiteId%5D/page/%5BpageId%5D/Modules/ModuleFilmstrip.tsx), [ModulePreview](../../apps/app/app/%5Busername%5D/site/%5BsiteId%5D/page/%5BpageId%5D/Modules/ModulePreview.tsx).

A position-based interpretation of the request would calculate each preview's horizontal center relative to its own row's visible center and map that distance to a bounded `rotateY`. Different widths need each item's actual center. The scroll-velocity example demonstrates another interpretation: lean while moving, then settle. The two can be combined if desired, but they produce different resting appearances. Motion's `useScroll` supports a scrollable container and an individual target along the horizontal axis, and `useTransform` maps motion values to output ranges. QRK already depends on `framer-motion`; the Motion+ carousel is a separate paid component. [Motion useScroll](https://motion.dev/docs/react-use-scroll), [Motion useTransform](https://motion.dev/docs/react-use-transform), [App package](../../apps/app/package.json).

For cursor tilt, measuring a stable outer frame and applying the visual transform inside it keeps the pointer reference and the selection target stable as the visible preview moves. Compose the position-based and pointer-based transforms deliberately, then return to the position-based pose on pointer exit. This is a proposed application of the examples, not a tested QRK implementation. The row clips overflow, so padding and shadow extents need visual checking at the top, bottom and ends of each row. Preserve the selection overlay and separate Brick action when testing interaction.

On devices whose primary input cannot conveniently hover, retain the scroll effect while leaving cursor tilt inactive. With reduced motion enabled, a static shadow can still communicate lift while scroll- and pointer-driven rotations are suppressed. Motion documents turning off parallax for reduced motion, and the CSS hover media feature identifies whether the primary input can hover. [Motion reduced motion](https://motion.dev/docs/react-use-reduced-motion), [CSS hover media feature](https://drafts.csswg.org/mediaqueries-5/#hover).

The examples establish patterns and available controls, not the right angle, shadow strength, or speed for QRK's previews. Those values require visual exploration with real Brick content and the existing selection and action controls.
