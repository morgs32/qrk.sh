# Service actor version repository

This Durable Object retains confirmed service command occurrences for one actor binding and computes that actor's selected resource changes. Constructor validation requires the internal tuple `actorName: '__service'`, `actorVersion: serviceVersion`, and `actorPath: '/'`; subsequent actor-name checks rely on that validation. This binding has no browser session; it runs the service version's automations and publishes their saved commands back through `ServiceChain`.

Registration stores a `startIndex` before the first addressed command is admitted. Registration holds the `serviceAutomationCatchup` recovery alarm. Internal activation returns without subscribing, avoiding a subscription callback into the held admission operation. The retained alarm resumes open groups, catches up from that frontier, and releases its hold. A confirmed occurrence enrolls matching runs for its addressed service version. Failed and skipped occurrences still advance the actor cursor. Recovery and confirmed group processing share one owner-local gate, so catch-up cannot interrupt a live invocation. Siblings read the same captured optimistic selected graph, run concurrently in isolated databases outside SQL transactions, and save their own result, failure, or explicit empty result. A saved output is staged against optimistic state, which is reconstructed from authoritative resources and unresolved pending operations. The next group starts after staging outcomes are durable; admission can finish later.

`commands` holds complete encoded input, source position, lifecycle results, selected delta, and publication acknowledgement. An automation output is retained there before it has a source position. `automationRuns.outputCommandRowId` and `pendingCommands.commandRowId` point at that row. The pending table stores replay mutations and queue bookkeeping without duplicating payload. The output outbox submits by run reference; `ServiceChain` reads the saved command from this internal binding and admits its original bytes. A retry reuses the saved command ID.

See [ServiceActorVersionRepo.ts](ServiceActorVersionRepo.ts), [executeTx.ts](execute/executeTx.ts), [makeServiceAutomations.ts](automations/makeServiceAutomations.ts), and the [real Worker test](automations/serviceAutomations.workerd.spec.ts). Fixed-schema changes require empty storage.
