---
title: Make a system
description: Define models, contracts, a session, and actor identity and authorization with Zerospin make methods.
---

This guide shows the direct shape for defining a small system. It keeps each exported piece visible so the relationships between models, contracts, session, aggregate owner, and system are easy to inspect.

## Imports

Import the builders, primitive descriptors, typed error shape, and Effect schema tools used by the system.

```ts
import * as sdk from '@zerospin/sdk';
import { makeSession } from '@zerospin/browser';
import { makeModelIdSchema } from '@zerospin/core/models/makeModelIdSchema.js';
import { Effect, Layer, Schema } from 'effect';
```

## Models

Models define the resource types in the system. Each model identity has explicitly authored versions. These models each declare their first version. The `User` model supplies this aggregate's user identity. `List` belongs to a user, and `Item` belongs to a list.

```ts
export const User = sdk.makeModelVersion(
  sdk.defineModel({ name: 'user', abbreviation: 'usr' }),
  {
    attributes: {
      name: sdk.primitives.text(),
    },
    indexes: [],
    version: '1.0.0',
  },
);

export const List = sdk.makeModelVersion(
  sdk.defineModel({ name: 'list', abbreviation: 'lst' }),
  {
    attributes: {
      name: sdk.primitives.text(),
      userId: sdk.primitives.ref({
        table: User.table,
        relation: 'user',
        inverse: 'lists',
      }),
    },
    indexes: [],
    version: '1.0.0',
  },
);

export const Item = sdk.makeModelVersion(
  sdk.defineModel({ name: 'item', abbreviation: 'tsk' }),
  {
    attributes: {
      listId: sdk.primitives.ref({
        table: List.table,
        relation: 'list',
        inverse: 'items',
      }),
      name: sdk.primitives.text(),
    },
    indexes: [],
    version: '1.0.0',
  },
);
```

## Contracts

Contracts define commands. Each contract has a payload shape, declared model versions, and a program. The program receives mutation constructors bound to those exact model versions.

`createList` creates a `List` resource and stores the user relationship on `userId`.

```ts
export const createList = sdk.makeContractVersion(
  sdk.defineContract('createList'),
  {
    payload: {
      id: sdk.primitives.foreignKey({ abbreviation: List.abbreviation }),
      name: sdk.primitives.text(),
      userId: sdk.primitives.foreignKey({ abbreviation: User.abbreviation }),
    },
    models: { list: List },
    program: props => {
      const { payload, models } = props;
      const { id, name, userId } = payload;
      return Effect.all({
        created: models.list.create({
          resourceId: id,
          attributes: {
            name,
            userId,
          },
        }),
      });
    },
    version: '1.0.0',
  },
);
```

`createItem` creates an `Item` resource and stores the list relationship on `listId`.

```ts
export const createItem = sdk.makeContractVersion(
  sdk.defineContract('createItem'),
  {
    payload: {
      id: sdk.primitives.foreignKey({ abbreviation: Item.abbreviation }),
      listId: sdk.primitives.foreignKey({ abbreviation: List.abbreviation }),
      name: sdk.primitives.text(),
    },
    models: { item: Item },
    program: props => {
      const { payload, models } = props;
      const { id, listId, name } = payload;
      return Effect.all({
        created: models.item.create({
          resourceId: id,
          attributes: {
            listId,
            name,
          },
        }),
      });
    },
    version: '1.0.0',
  },
);
```

`updateList` changes the list name with the `List` model's matching versioned update schema and constructor.

```ts
export const updateList = sdk.makeContractVersion(
  sdk.defineContract('updateList'),
  {
    payload: {
      id: sdk.primitives.foreignKey({ abbreviation: List.abbreviation }),
      name: sdk.primitives.text(),
    },
    models: { list: List },
    program: props => {
      const { payload, models } = props;
      const { id, name } = payload;
      return Effect.all({
        updated: models.list.update({
          resourceId: id,
          attributes: { name },
        }),
      });
    },
    version: '1.0.0',
  },
);
```

## Session

The session selects models and contracts from one aggregate version. Its lock must match those definitions exactly and include every selected contract's declared mutation models. Sessions are not registered on the server aggregate. `makeSession` receives an identity schema shared with the selected actor. Aggregate identities require a string `aggregateId`. The session has no independent version.

```ts
// Share this browser-safe identity schema with the selected server actor.
export const listIdentitySchema = Schema.Struct({
  aggregateId: Schema.String,
  userId: makeModelIdSchema(User),
});
// Supply API URL, publishable key, and application capabilities in this layer.
export const listSession = makeSession({
  kind: 'aggregate',
  sessionName: 'main',
  systemName: 'system1',
  identitySchema: listIdentitySchema,
  layer: applicationLayer,
  aggregateName: 'user',
  aggregateVersion: '1.0.0',
  actorName: 'default',
  actorVersion: '1.0.0',
  contracts: {
    createList: { contract: createList },
    createItem: { contract: createItem },
    updateList: { contract: updateList },
  },
  models: {
    list: List,
    item: Item,
    user: User,
  },
});
```

Each session owns its runtime. Its application layer is acquired lazily and reused
until `session.dispose()`, including for local guards and commands. Call
`session.runtime.runPromise(effect)` to run an Effect with those services.
Reinitializing the same session preserves its store but creates a fresh runtime;
read `session.runtime` again after reinitialization. Disposing a session preserves
its saved backup.

## Actor identity and authorization

An actor declares its identity schema and selection path separately from its
server authentication policy. This example explicitly accepts supplied identity.
Production actors that verify credentials instead declare
`authentication: { credentialsSchema, authenticate }`; their callback returns the
same identity shape, and their sessions initialize with `{ getCredentials }`.

```ts
const identity = sdk.makeActorIdentity({
  schema: listIdentitySchema,
  actorPath: RoutePattern.parse('/:userId'),
});
const db = sdk.makeActorDbVersion({
  models: { user: User, list: List, item: Item },
});
const defaultActor = sdk.makeAggregateActorVersion(
  { name: 'default' },
  {
    version: '1.0.0',
    db,
    identity,
    authentication: 'none',
    contracts: { createList, createItem, updateList },
    queries: {
      user: db.query.user.findMany({
        where: { id: { eq: identity.sql.placeholder('userId') } },
      }),
      list: db.query.list.findMany({
        where: { user: { id: { eq: identity.sql.placeholder('userId') } } },
      }),
      item: db.query.item.findMany({
        where: {
          list: { user: { id: { eq: identity.sql.placeholder('userId') } } },
        },
      }),
    },
  },
);
export const user = sdk.makeAggregateVersion(
  sdk.defineAggregate({ name: 'user' }),
  {
    version: '1.0.0',
    models: { user: User, list: List, item: Item },
    actors: { default: defaultActor },
  },
);
export const system = sdk.makeSystem({
  name: 'system1',
  aggregates: { user: { '1.0.0': user } },
  services: {},
});
await listSession.initialize({
  identity: { aggregateId: 'acct_example', userId },
});
```

Admission validates the supplied identity or verified callback result. Actor
`authorize` callbacks receive that identity and current database access. Selection
paths determine the actor view; the session lock further limits delivered models
and accepted commands. Credentials are never saved in commands or backups.

A direct session captures identity at initialization and reuses it on reconnect.
Dispose and initialize again to change identity. Verified sessions obtain fresh
credentials on reconnect. Both forms retain the server-accepted identity in
session state and commands; offline restoration cannot switch a direct session
to another identity's backup.
