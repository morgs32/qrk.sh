# Work-in-progress component development in Next.js

Researched 2026-11-11 against the Next.js documentation, the upstream Next.js example, and the Vercel and Storybook guides.

## What Next.js shows

The standard development loop is to run `next dev`, render the component on a page, and iterate in the browser with Fast Refresh. The official dashboard course shows this directly by editing the homepage and its UI, then previewing the changes on the running app. Fast Refresh rerenders edited components and preserves local state when it can. [Next.js CLI](https://nextjs.org/docs/app/api-reference/cli/next#next-dev-options), [Fast Refresh](https://nextjs.org/docs/architecture/fast-refresh), [Next.js Learn](https://nextjs.org/learn/dashboard-app/css-styling).

Next.js also publishes an official `with-storybook` example that you can scaffold with `create-next-app --example with-storybook`. The example uses Storybook's Webpack-based `@storybook/nextjs` adapter. Vercel's guide describes using Storybook to develop one component at a time without arranging application or database state. [Next.js Storybook example](https://github.com/vercel/next.js/tree/canary/examples/with-storybook), [Vercel Storybook guide](https://vercel.com/kb/guide/storybook-with-vercel).

Storybook's own guidance favors `@storybook/nextjs-vite` for Next.js apps that can use Vite. It supports framework features such as images and fonts and provides router and other module mocks. Its experimental React Server Component support renders in the browser and may require mocks for server-side resources. A Next.js page can exercise actual App Router layouts and server behavior when those are part of the work. [Storybook Next.js with Vite](https://storybook.js.org/docs/get-started/frameworks/nextjs-vite), [Next.js Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components).

## What that looks like in QRK Web

- **One in-app fixture.** A normal App Router page can import the WIP component and pass hard-coded props while it runs under `next dev`. This follows from Next.js page conventions. QRK already renders fixed sections at `/ordered-outline`, which Web's proxy lists as public. A local-only fixture could use QRK Web's existing `/__dev` prefix, which its proxy gates to development. The App Router's underscore escape lets a folder such as `%5F%5Fdev` produce that URL segment. [Next.js project structure](https://nextjs.org/docs/app/getting-started/project-structure), [QRK OrderedOutline page](../../apps/web/app/ordered-outline/page.tsx), [QRK Web proxy](../../apps/web/proxy.ts), [QRK dev sign-in route](../../apps/web/app/%255F%255Fdev/log-me-in/%5Bemail%5D/route.ts).
- **Reusable isolated states.** A story gives a component a named set of props or a fixture. QRK's button link examples show variants and sizes, while the WallViewer story mounts a fixed published snapshot with representative Bricks. Web currently uses the generic `@storybook/react-vite` framework and its own Vite configuration. The Storybook Next.js adapter above is a separate integration. [Writing stories](https://storybook.js.org/docs/writing-stories), [Button Links stories](../../apps/web/components/ui/button.stories.tsx), [WallViewer story](../../apps/web/library/WallViewer.stories.tsx), [QRK Web Storybook config](../../apps/web/.storybook/main.ts), [QRK Web Vite config](../../apps/web/vite.storybook.config.mts).
- **Automated checks.** The Next.js testing guide documents Cypress component tests for mounting a component independently. It recommends end-to-end testing for async Server Components. This addresses regression checks alongside the visual development workflows. [Next.js Cypress guide](https://nextjs.org/docs/app/guides/testing/cypress#creating-your-first-cypress-component-test).
