# Aggregate actor version repository

This Durable Object projects complete terminal aggregate command results into one actor’s confirmed selected graph. It stages caller commands against a disposable optimistic view. Staging checks the actor guard and original contract program/guard. AggregateVersionRepo prepares the authoritative program and revalidates aggregate access and contract guards inside its command transaction.

Projection applies locally retained model-operation bodies in their original order, preserving model versions and source timestamps. It skips retained async emissions without starting producers. Projection does not rerun the originating program or query an upstream owner. Each receiving position atomically commits confirmed resources, pending-command resolution, its checkpoint, and one flat `IBrowserCommand` row, including empty selected deltas. Owning completions retain admission and execution status, timing, failure, and result; other recipients receive null phase fields. Duplicate receiving positions do not publish again.

`commands` retains aggregate command inputs and lifecycle results. `stagedCommands` retains staging time, ordered optimistic operations, and resolution independently of delivery. `stagedAggregateCommandOutbox` carries the full staged command to AggregateChain and deletes after durable admission; unresolved journal entries continue supplying optimism until terminal resolution.

Staging reconstructs the full resource graph and replays unresolved prepared operations into a scoped scratch database. Earlier accepted siblings supply the state for later guards. A declared rejection discards that candidate without allocating a staging position; an infrastructure or commit failure leaves no new retained input, operations, or delivery work. A duplicate stable command returns its retained staging outcome without preparing it again; changed input or provenance under that ID fails explicitly. The final transaction checks that confirmed progress and pending work still match the prepared basis. A changed basis retries preparation, while actor write permits serialize the durable commit with projection.

Reconstruction uses saved operations, generated IDs, and staging timestamps. It does not run programs, mappers, guards, or submission. Updates apply to the current confirmed rows rather than restoring stale staged rows. A command whose operations can no longer apply stays unresolved and contributes no partial optimistic changes. Copying the full graph preserves relationship-driven selection entry and exit.

The outbox records recognized admission refusals and resolves their pending contribution without moving confirmed resource rows or checkpoints. A retained admission result, including a failed result, is successful delivery. Transport failures retain delivery work for retry. The socket waits for `getStagedAdmission`; a local server staging outcome is not an admission receipt. Browser journal completion still comes from ordered terminal actor output or snapshot outcome recovery.

`browserCommandOutbox` carries `id`, `commandName`, selected `delta`, and nullable `admission`/`execution` objects with receiving checkpoint and private recipient metadata. It deletes after the actor chain durably retains the command in `browserCommands`. Browser snapshots capture confirmed resources and checkpoint together, publish through that checkpoint, then read the requesting node’s contiguous outcome prefix from actor-chain history at that position. Queue deletion cannot erase outcomes or reset positions.

AAVR has no listener declarations, invocation groups, or projection gates. The historical listener/automation scheduler was removed; explicit mapped async emissions are owned by VersionRepo execution and recovery. Changed fixed schemas require empty storage.
