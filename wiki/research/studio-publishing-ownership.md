# Studio publishing ownership

Researched against current source and Plan 025 on 2026-10-16. Repository source search excluded generated output and dependencies. No implementation, builds, or tests were performed.

## Finding

Publication belongs in QRK. Its models, commands, and controls already live there. The questionable part is the two Library snapshot exports: they choose part of QRK's persisted publication format, while their only runtime consumers are QRK's page snapshot files. The recommendation is to fold that serialization into those existing QRK files. [Schema consumer](/Users/morgs32/GitHub/qrk.sh/apps/zerospin/src/aggregates/user/snapshots/pageSnapshotSchema.ts:1), [Projection consumer](/Users/morgs32/GitHub/qrk.sh/apps/zerospin/src/aggregates/user/snapshots/makePageSnapshot.ts:1).

## Consumer and deletion test

The two helpers have public Library subpaths and build entries. Source search found only QRK's schema/projection importing them; Library's factory additionally imports its schema for its return type. [Exports](/Users/morgs32/GitHub/qrk.sh/apps/library/package.json:57), [Build](/Users/morgs32/GitHub/qrk.sh/apps/library/vite.lib.config.ts:36), [Type import](/Users/morgs32/GitHub/qrk.sh/apps/library/libraryModule/snapshots/makeWallSnapshot.ts:5), [QRK imports](/Users/morgs32/GitHub/qrk.sh/apps/zerospin/src/aggregates/user/snapshots/makePageSnapshot.ts:1).

There is no independent Library consumer demonstrating this content format. Its renderer accepts a session/wall ID and queries models; standalone backup uses the existing session mechanism. Neither consumes WallSnapshot. [Renderer](/Users/morgs32/GitHub/qrk.sh/apps/library/lib/BrickWall.tsx:46), [Queries](/Users/morgs32/GitHub/qrk.sh/apps/library/lib/BrickWall.tsx:89), [Backup configuration](/Users/morgs32/GitHub/qrk.sh/apps/library/session/createLibraryStandaloneSession.ts:42).

Deleting the package seam would not eliminate serialization; that work would live once in QRK's existing page snapshot module. Reuse across the three commands and Studio remains intact through `makePageSnapshot`. Its current callers already share the same policy, rather than demonstrating independent adapters. ## Recommendation and counterargument

The strongest keep-Library argument is locality: Library understands its content. That supports Library owning the model codecs and editing invariants. The snapshot helper adds no module-specific validation or rendering behavior; it copies saved fields and chooses what publication retains. My inference is that this policy belongs beside QRK's stored snapshot and dirty comparison. QRK can continue deriving exact field codecs from the existing `libraryModule` export. [Field derivation](/Users/morgs32/GitHub/qrk.sh/apps/library/libraryModule/snapshots/wallSnapshotSchema.ts:10), [Projection](/Users/morgs32/GitHub/qrk.sh/apps/library/libraryModule/snapshots/makeWallSnapshot.ts:19), [Existing model export](/Users/morgs32/GitHub/qrk.sh/apps/library/package.json:53).

Recommended follow-up: fold the wall schema/projection into the existing QRK page snapshot files and remove the two Library files/exports/build entries. Preserve content shape, exclusions, and ordering. No new seam or helper is needed. Plan 025 and READMEs explicitly recorded the current split; they explain its origin but do not establish a requirement to retain it. Reconcile those descriptions if ownership changes. This note makes no implementation changes or compatibility claims.
