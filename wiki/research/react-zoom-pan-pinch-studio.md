# React Zoom Pan Pinch for the Studio tree story

Researched 2026-10-20. Planning evidence only; no dependency installation, implementation, or browser interaction was performed.

## Source and version

The library's [official README](https://github.com/BetterTyped/react-zoom-pan-pinch#examples) composes `TransformWrapper` around `TransformComponent`, which contains the DOM to transform. The [npm latest metadata](https://registry.npmjs.org/react-zoom-pan-pinch/latest) resolved to **4.2.0** and Git commit [`34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f`](https://github.com/BetterTyped/react-zoom-pan-pinch/tree/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f) during this research. Findings below refer to that release, rather than the moving default branch.

## Initial scale, sizing, and bounds

1. **50% needs both an initial scale and a lower minimum.** Use `initialScale={0.5}` and explicitly set `minScale` to at most `0.5`. The default minimum is `1`, and initialization clamps `initialScale` into the configured range. Default maximum is `8`. [Defaults](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/constants/state.constants.ts#L12-L26), [initialization](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/utils/state.utils.ts#L10-L17).
2. **The viewport needs explicit dimensions.** `TransformComponent` exposes `wrapperStyle` and `contentStyle`. Its wrapper defaults to `fit-content` width and height with `overflow: hidden`; its content also defaults to `fit-content`, with transform origin `0 0`. Fill the intended frame's available content area with the wrapper, and retain a deliberate unscaled layout width for the tree. This sizing advice is an inference from the component and CSS, not an applied layout. [Component props/rendering](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/components/transform-component/transform-component.tsx), [stylesheet](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/components/transform-component/transform-component.module.css#L1-L24).
3. **Scaling changes rendering, while layout remains unscaled.** The library applies `translate(...) scale(...)`; its bounds use unscaled `offsetWidth`/`offsetHeight` multiplied by scale against wrapper `clientWidth`/`clientHeight`. A 50% view does not automatically lay the tree out at twice its normal width. [Transform](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/utils/styles.utils.ts#L7-L16), [size calculation](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/bounds/bounds.utils.ts#L10-L35).
4. **Initial centering, ongoing centering, and fitting are different.** `centerOnInit` centers both axes at the current scale. `centerZoomedOut` changes bounds: when content is smaller than the wrapper along an axis, it fixes that axis to its centered position. `fitOnInit` computes a fitting scale and takes precedence over simple centering, so leave it off when exactly 50% is the requirement. All three default to false; `limitToBounds` defaults to true. [Defaults](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/constants/state.constants.ts#L18-L24), [bounds](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/bounds/bounds.utils.ts#L37-L67), [initial-layout behavior](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/instance.core.ts#L772-L820).

## Nested dragging and controls

1. **Release 4.2.0 protects native draggable descendants.** Panning refuses targets inside an ancestor matching `[draggable="true"]`, and refuses editable targets such as inputs and contenteditable regions. Accepted mouse pans call `preventDefault` and `stopPropagation`, so these exclusions matter for native HTML drag initiation. [Panning eligibility](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/pan/panning.utils.ts#L13-L49), [target helpers](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/utils/helpers.utils.ts#L16-L55), [mouse-pan start](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/instance.core.ts#L443-L472).
2. **Ordinary buttons and links need a deliberate pan policy.** They are absent from the editable-target tags. `panning.excluded` can exclude tag names or plain class names and matches their descendants. For example, `excluded: ["button", "a"]` preserves those control targets. Avoid assuming it accepts arbitrary CSS selectors: the helper also prepends `.` to each entry, which can make an attribute-selector entry invalid. These are source-derived integration cautions, not verified behavior of QRK's complete tree. [Target helpers and exclusion matching](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/utils/helpers.utils.ts#L5-L55).
3. **Pan gestures are configurable.** Left, middle, and right mouse panning default to enabled; `panning.activationKeys`, per-button flags, and `panning.disabled` can restrict them. A story should choose its pan policy explicitly rather than let an unqualified mouse pan compete with existing tree interactions. This is a recommendation. [Defaults](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/constants/state.constants.ts#L43-L53), [gesture checks](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/instance.core.ts#L443-L465).

## Wheel, touch, and double-click

1. **Defaults are interactive.** Wheel zoom, touch pinch, and double-click zoom are enabled; trackpad panning is disabled. Double-click defaults to zooming in. Keyboard navigation is opt-in. [Defaults](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/constants/state.constants.ts#L27-L75).
2. **Canvas-style wheel behavior is available.** `wheel={{ wheelDisabled: true }}` rejects ordinary non-Ctrl wheel zoom while allowing Ctrl wheel/pinch zoom. Pairing it with `trackPadPanning={{ disabled: false }}` lets non-Ctrl wheel deltas pan when wheel zoom does not claim the event. Despite the option's name, the eligibility code does not require hardware detection, so ordinary mouse-wheel deltas can also pan. This is an available configuration, not a settled product choice. [Wheel and wheel-pan eligibility](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/wheel/wheel.utils.ts#L5-L69).
3. **Double-click should be chosen explicitly for the tree.** `doubleClick={{ disabled: true }}` avoids an extra zoom action while interacting with its existing controls. This is a recommendation. Touch panning and pinch are separate interactions; no mobile drag-and-drop compatibility was tested here. [Touch and double-click dispatch](https://github.com/BetterTyped/react-zoom-pan-pinch/blob/34abc1ffbc124f2adf9c959f81ce6c6f2c2f219f/src/core/instance.core.ts#L566-L647).

## Planning recommendation and verification boundary

1. Keep the existing frame outside `TransformComponent` so its controls remain unscaled; transform only the tree content. The exact frame component is a local composition decision.
2. Start at `0.5`; a trial range of `0.25`–`2` is a reasonable proposal for comparing overview and readable content, not a library requirement. Use a fixed `0.5` view instead if the story is only meant to demonstrate a zoomed-out composition.
3. Do not add coordinate conversion solely because the tree is transformed. CSSOM View specifies that client rectangles account for ancestor transforms. Comparing those rectangles with pointer client coordinates is compatible in principle; complete drop-target, insertion-indicator, drag-preview, menu, and clipping behavior still needs manual verification in the new story. [CSSOM View, Element geometry](https://drafts.csswg.org/cssom-view/#dom-element-getclientrects).
4. The existing [Pragmatic Tree story](../../apps/app/components/PragmaticTree.stories.tsx) is the local integration reference. This note does not assert that its entire drag-and-drop implementation works at 50%, and introduces no new drag coordination or test infrastructure.
