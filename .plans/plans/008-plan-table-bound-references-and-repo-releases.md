# 008 — Table-Bound References and Repo Releases Implementation Plan

**Source spec:** `../archived/008-spec-table-bound-references-and-repo-releases.md`

## Summary

1. Replace the ambiguous ID primitive with exclusive primary-key, cursor, prefixed-value, and table-bound ref semantics.
2. Derive Drizzle schemas and acyclic relations from concrete table graphs while preserving relational model queries.
3. Migrate existing tables without synthetic keys, promoting only the eight approved values and retaining ten logical identities.
4. Prefix registered system-worker Durable Object names and persist exact repo names in subscriber/subscription rows.
5. Add category-scoped controller releases and retain the approved schema-only DevZerospinApis tables without population.
6. Remove obsolete source APIs and documentation in the same pass without compatibility aliases or state fallbacks.

## Implementation

1. Establish the new primitive taxonomy in core.
   1. Replace the ID enum member with `PrimaryKey` and `Prefixed`, retaining `Cursor` and the existing non-prefixed primitive kinds.
   2. Remove `IIdDescriptor`/`IAnyIdDescriptor`; add the approved public `IPrimaryKeyDescriptor` and `IPrefixedDescriptor`; reshape the approved `IRefDescriptor` around a concrete table target plus mandatory relation names.
   3. Implement `primitives.primaryKey({ abbreviation })` with non-empty-prefix validation and invariant non-null/unique metadata.
   4. Implement `primitives.prefixed({ abbreviation, nullable?, unique? })` with the existing abbreviation-prefixed schema behavior.
   5. Remove primary-key options from text and cursor factories, and remove model/autogenerate behavior from raw primitives.
   6. Update Effect/JSON schemas, encoded/decoded inference, Drizzle builders, migration SQL, row/column inference, and exhaustive primitive switches.
   7. Ensure encoded descriptors omit absent state rather than serializing false or undefined properties.
   8. Remove `primitives.id`, `PrimitiveKind.Id`, and all ID descriptor branches without aliases.

2. Make tables and refs the single relation source.
   1. Extend `ITable`/`makeTable` inference so a ref retains its concrete target table and the target table's sole primary-key column type.
   2. Change `primitives.ref` to require `{ table, relation, inverse }`, derive its abbreviation from the target primary key, and retain nullable/unique options.
   3. Make table shapes reject refs with missing relation names and reject refs targeting a table with zero or multiple primary keys.
   4. Encode refs as stable target/relation metadata while omitting the runtime table object.
   5. Replace `makeDrizzleRelationsFromModels` and `makeDrizzleRelationsFromSchema` with the approved `makeDrizzleRelationsFromTables(tables)` defining-module export.
   6. Implement relation derivation with verbose annotated table/column loops. Build forward `one` relations and inverse `one`/`many` relations from ref uniqueness.
   7. Add the approved explicit DFS validation in the relation module. Reject cycles, targets outside the database, duplicate table names, duplicate forward/inverse names, and invalid target keys before constructing relations.
   8. Emit Drizzle relations only; do not call SQLite `.references(...)` or add foreign-key migrations.

3. Move database factories onto table graphs.
   1. Change `makeDbConfig` to accept `{ tables }`, validate the table graph, and derive both schema and relations.
   2. Change `makeResourceDbConfig` to collect each supplied model's `model.table`, merge optional `otherTables`, and delegate to the same table-based config path.
   3. Preserve the branded resource database config and typed `db.query` surface.
   4. Migrate core tests and consumers that manually build `{ schema, relations }` to pass table maps or use `makeResourceDbConfig`.
   5. Remove direct caller imports of the two deleted relation builders and remove manual empty-relation objects.

4. Give models table and payload primary-key boundaries.
   1. Make `makeModel` construct one table containing synthesized `id`, `modelName`, timestamps, version, and declared attributes; expose it as `model.table`.
   2. Synthesize `id` with `primitives.primaryKey({ abbreviation })` and reject additional primary-key/autogenerated model attributes at compile time and runtime.
   3. Add `Model.primaryKey({ autogenerate })` with a mandatory boolean literal and model-bound payload identity inference.
   4. For `autogenerate: false`, require the prefixed value. For `true`, accept omission/null at input and mint the value through the existing Cuid service during payload validation.
   5. Make contract payload types reject table refs and raw primary-key descriptors while accepting model-produced primary-key descriptors.
   6. Migrate create, update, delete, filter, and relationship payloads to the appropriate explicit autogeneration value.
   7. Do not add contract-result inspection, a mutation graph validator, or another named descriptor type.

5. Migrate core and package consumers by value semantics.
   1. Convert command, block, log, span, link, shared-worker, session, and other true row identities to `primitives.primaryKey` with their existing abbreviations.
   2. Convert every ordered production position still expressed as an ID to `primitives.cursor`, preserving nullability and uniqueness.
   3. Convert opaque, polymorphic, external, cross-database, provenance, and self-context IDs to `primitives.prefixed`.
   4. Convert model attributes to concrete table refs with explicit forward and inverse names; order model declarations topologically and keep the graph acyclic.
   5. Convert SystemLogRepo links to refs only where the target is a concrete same-database table and the graph remains acyclic; retain self/cross-store identities as prefixed values.

6. Apply the approved primary-key policy to system-worker and supporting tables.
   1. Promote `finalizedBlocks.lastAccountCursor`, `accountBlockOutbox.lastAccountCursor`, `actorBlocks.lastAccountCursor`, `actorBlockOutbox.lastAccountCursor`, `serviceBlocks.lastServiceCursor`, `serviceCursors.serviceCursor`, `serviceBlockOutbox.lastServiceCursor`, and `SystemRepo.accounts.accountId` to `primitives.primaryKey`.
   2. Remove only the unique indexes made redundant by those primary keys; retain independent cursor/index ordering constraints.
   3. Preserve unique-index-only logical identities on AccountBlockRepo mutations, AccountRepo replicated resources, ActorRepo graph, AuthorizationRepo authorizations, FrontendBlockRepo frontend blocks, FrontendRepo graph/pushed mutations/frontend block outbox, SystemRepo repos, and FixtureRepo fixture values.
   4. Do not add synthetic key columns or turn numeric/heterogeneous/composite identities into prefixed primary keys.
   5. Use refs only for same-database single-target relations; keep cross-Durable-Object names and delivery watermarks as primary-key/prefixed/cursor values according to their own role.

7. Prefix registered system-worker repo names end-to-end.
   1. Add the locked repo abbreviations to the existing abbreviation registry: `sysrepo`, `acctrepo`, `atzrepo`, `actrrepo`, `frtrepo`, `svcrepo`, `acctbrepo`, `actrbrepo`, `frtbrepo`, `svcbrepo`, and `syslogrepo`.
   2. Add required `abbreviation` input to `makeRepoUtils` and `makeRepoNameUtils` without introducing a wrapper or separate repo-name service.
   3. Make names as `${abbreviation}_${existingRouteName}`. Parse by validating/removing the exact prefix before invoking the existing route matcher.
   4. Configure SystemRepo, AccountRepo, AuthorizationRepo, ActorRepo, FrontendRepo, ServiceRepo, AccountBlockRepo, ActorBlockRepo, FrontendBlockRepo, ServiceBlockRepo, and SystemLogRepo with their one locked prefix.
   5. Leave FixtureRepo, DevZerospinApis, SystemLogAgent, tests, BackendRepo, and ControllerRepo outside prefix registration.
   6. Update all repo-opening helpers, `getByName` calls, public explorer methods, sibling-repo calls, and forwarded names to use the prefixed result rather than rebuilding names locally.
   7. Update the React actor-block websocket constructor to use the prefixed actor repo name.
   8. Add wrong-prefix, missing-prefix, round-trip, and SystemRepo fixed-name tests.
   9. Do not read old names, try an unprefixed fallback, migrate object state, or add deprecated overloads.

8. Rename subscriber and subscription row identities.
   1. Rename ServiceBlockRepo `accountSubscribers.name` to `accountRepoName` and use an `acctrepo` primary key.
   2. Rename AccountBlockRepo `actorSubscribers.name` to `actorRepoName` and use an `actrrepo` primary key.
   3. Rename ActorBlockRepo `frontendSubscribers.name` to `frontendRepoName` and use a `frtrepo` primary key.
   4. Rename AccountRepo `serviceSubscriptions.serviceName` to `serviceRepoName` and use an `svcrepo` primary key.
   5. Update every public method prop, same-named Effect function prop, insert row, conflict target, predicate, queue read, drain function, and `getByName` delivery lookup.
   6. Preserve account/service/actor/frontend domain names in their separate existing columns; do not derive them back from repo names.
   7. Extend workerd tests through subscription insertion, queue recovery, alarm/drain, successful delivery, and retry/error paths.

9. Add category-scoped controller releases.
   1. Add the locked release abbreviations: `sysrel`, `acctrel`, `actrrel`, `frtrel`, and `svcrel`.
   2. Require `version` in account, actor, and service controller factories while preserving the required frontend and system versions.
   3. Add an inline `getRelease()` method to each controller that returns its category abbreviation plus version with exact template-literal inference.
   4. Do not add a shared release helper.

10. Keep DevZerospinApis on the approved schema-only controller tables.
   1. Convert DevZerospinApis through its existing `makeRepo({ repoUtils })` boundary, retain `/:systemRelease`, and omit `repoType` registration.
   2. Preserve the seed receipt, command journal, readiness Promise, Cap'n Web fetch behavior, release equality check, and Wrangler migration.
   3. Define only `accountControllers`, `frontendControllers`, `actorControllers`, and `systemControllers`, each with one non-null text primary-key `release` column using its controller release abbreviation.
   4. Add no `serviceControllers` table, controller rows, timestamps, or population behavior.

11. Synchronize architecture and static patterns.
   1. Update SystemApi, DeploySystem, Blockchain, FrontendApi/websocket, bootstrap-session, and model relation architecture citations after final source edits.
   2. Update encoded-shape, table-shape, typecheck, naming, primary-key/ref/prefixed, and repo-name patterns; include no compatibility examples.
   3. Refresh wiki source hashes, line citations, index/glossary entries when affected, and append the required wiki log entry.

## Guardrails

1. Preserve all unrelated WIP and existing comments.
2. Do not add compatibility aliases, deprecated overloads, old Durable Object name fallback, or old database-state fallback.
3. Do not add SQLite foreign keys, synthetic primary-key columns, payload refs, cyclic/lazy/union refs, or controller-table population.
4. Do not add helper functions beyond the approved relation-builder replacement or named types beyond the three approved descriptor types.
5. Use explicit annotated relation/cycle loops; do not introduce a generic graph abstraction.
6. Do not add `ALLOWED_CAST` markers. Stop for explicit user permission if an unavoidable cast would require one.
7. Keep async methods at runtime boundaries and preserve same-named system-worker repo method folders.
8. Complete happy, failure, retry, and resume paths for every renamed repo delivery boundary in the same implementation pass.
