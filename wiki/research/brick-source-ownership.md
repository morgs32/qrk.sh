# Brick source and Worker ownership

Researched 2026-11-11. Source links capture the layout before Plan 068.

- A Brick's declaration and React view have different consumers. Link's versioned definition supplies state, sizing, and default spec data. App registers the React views, while Zerospin validates stored state and spec documents against Brick declarations. That supports grouping each Brick's files together while retaining the definition and React entrypoints. [Link definition](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/bricks/src/link/definition/linkV1.ts#L40) · [App view registrations](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/app/modules/modulesHash.ts#L1) · [Zerospin state validation](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/zerospin/src/aggregates/user/contracts/brick/UpdateBrickV6.ts#L31)
- Shared inputs, layout components, surface styles, and tokens already serve multiple Bricks. The Form Inputs story demonstrates these controls independently of any one Brick. Shared JSON Render metadata and schema helpers serve generation and validation as well as the React registry, so they belong in the React-free definition layer. [Form Inputs story](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/bricks/src/react/FormInputs.stories.tsx) · [Layout metadata](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/bricks/src/definition/layoutComponentMetadata.ts#L20)
- Bricks' `rpc/` exports describe the wire interface. The concrete `LibraryApi` dispatches Brick lookups and generates specs from the Brick catalog. GitHub and Instagram also use `BackendRepo` to record provider responses. These implementations belong together under the Bricks Worker source directory. [Type-only exports](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/bricks/package.json#L27) · [RPC implementation](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/api/modules/LibraryApi.ts#L21) · [Provider response store](https://github.com/morgs32/qrk.sh/blob/d1d6e568421f3a5ae8712c85ee285453ba2189f5/apps/api/modules/instagram/getInstagramProfile.ts#L233)
- API already dispatches `/rpc` separately from upload and asset requests. It can import the Bricks implementation and continue to export the same Durable Object classes from its existing entrypoint. The same URL serves browser calls and Zerospin's recorded spec generation. Moving to another Worker deployment would add a namespace transfer decision.
