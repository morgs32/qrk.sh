# Form feedback for Brick sidebar autosave

## shadcn patterns

- **Help and validation.** `Field` stacks the label, control, optional `FieldDescription`, and `FieldError`. The validation examples set `data-invalid` on the field wrapper and `aria-invalid` on the control. The Base UI registry's `FieldError` renders `role="alert"`. Associate the input with its help and error IDs using `aria-describedby`. [Field documentation](https://ui.shadcn.com/docs/components/base/field#validation-and-errors), [Field source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/ui/field.tsx), [W3C form notifications](https://www.w3.org/WAI/tutorials/forms/notifications/)
- **Pending work.** The `InputGroup` spinner examples put a spinner and optional status text alongside the input. The Next.js guide shows disabling controls during explicit submission. The input group example is a visual pattern, and the Brick form still owns commit timing and cancellation. [Input Group spinner](https://ui.shadcn.com/docs/components/base/input-group#spinner), [Next.js pending states](https://ui.shadcn.com/docs/forms/next#pending-states)
- **Broader feedback.** `Alert` provides an in-place callout with a destructive variant and optional action. Toast provides temporary feedback, including a promise example that updates one toast through loading, success, and error. [Alert](https://ui.shadcn.com/docs/components/base/alert#destructive), [Toast](https://ui.shadcn.com/docs/components/base/toast#promise)

## Recommended Brick behavior

- Put concise format help under the field when the accepted input needs explanation. Figma can show a short URL example. An untouched empty field starts neutral. Show actionable validation feedback for an invalid draft when the user tries to commit on blur or Enter, and update the feedback as they correct it. The idle timer may check validity silently while someone is still typing. [Field anatomy](https://ui.shadcn.com/docs/components/base/field#anatomy), [W3C inline feedback](https://www.w3.org/WAI/tutorials/forms/notifications/#in-line-feedback)
- Show a compact inline status while a lookup is active, such as “Fetching Figma preview…”, and keep the input editable so a new draft can supersede it. Give the status a polite live region and treat its spinner as decorative. Once the accepted preview updates, let that visible result confirm the change. A local `onSave` acceptance alone gives no evidence of remote durability. [Input Group spinner](https://ui.shadcn.com/docs/components/base/input-group#spinner), [W3C status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [Brick form staging](../../apps/app/modules/README.md#brick-forms)
- Keep failure feedback in the sidebar with the draft. Put a source-specific failure beside the field, mark it invalid when the value needs correction, and give provider outages or staging failures a separate local error message. Use a form-level destructive alert when the issue spans fields. Preserve the prior preview and let the user retry a failed text commit with Enter or blur. Frequent autosaves fit local status better than temporary toasts. [Field validation](https://ui.shadcn.com/docs/components/base/field#validation-and-errors), [Alert](https://ui.shadcn.com/docs/components/base/alert#destructive), [Toast](https://ui.shadcn.com/docs/components/base/toast)
