# Repo schema, activation, and alarms

**Every production Durable Object Repo has one immutable physical schema.** Use `makeFixedDORepo`; it provisions the current schema once, records the bootstrap marker only after initialization succeeds, and performs no schema work on a marked cold activation. `makeMigratableDORepo` is the evolving-schema sibling (ordered SQL migrations replayed on every activation, including after bootstrap); production Repos stay on `makeFixedDORepo` until explicitly switched. Do not add schema targets, checked-in SQL histories, CLI migration generate/check, or Worker-version routing for schema compatibility. Changed `makeFixedDORepo` schemas require empty storage.

**DO alarms are owned by the common Repo base.** Repos inherit `alarmRegistry` and `alarm()` from `makeDORepo`; do not add private registries, alarm overrides, or per-Repo `alarm/alarm.ts` dispatch wrappers. Queue factories synchronously register their lazy drain Effects. Subscriptions belong to `onDOActivation()`, not alarm registrations. Do not add a Repo alarm hook or DOConfig alarm callback. Registration performs no storage access or delivery. Every alarm runs all registered operations against durable state, independently of in-memory leases, and awaits every outcome before propagating combined failures. Each operation retains responsibility for its own alarm holds and releases.

**DO activation is owned by the common Repo base.** Before storage access, provisioning, bootstrap, or subscriptions, the common base serializes the executing bundle and requires matching accepted SystemRepo locks through registration. Registration never creates locks and remains recorded if later initialization fails. SystemRepo is exempt from self-registration. Override `onDOActivation()` with a named Effect for per-activation preparation and source subscription; the base runs it after schema/bootstrap and before completing its constructor concurrency block. `ready()` explicitly wakes a Repo. Queue factories have no readiness callbacks. Initialize every declared source from the selected authored snapshot, then await `subscriber.subscribe()` (catch up, then enroll) during activation. Do not hold an execution permit or database transaction across subscription RPCs. Read-time refresh uses `catchup()` without re-enrollment. Queue drains own alarms and delivery recovery; retain queue holds before committing pending delivery. Source enrollment must not acquire a drain semaphore that may be waiting for the subscribing Repo to activate. Service dependencies are known from `aggregate.services`; later resource enrollment does not create subscriptions or rewind source cursors. See the [Repo lifecycle README](../../../packages/system-worker/src/makeDORepo/README.md) and [fanout README](../../../packages/system-worker/src/makeFanoutQueue/README.md). Source-bound subscriber accessors validate the service pin against the selected aggregate definition and require its persisted `services` cursor before returning a capability.
