# shadcn control sizing in editor headers

Researched November 11, 2026. This covers Studio's Page controls and Publish Site pair, the referenced shadcn editor, and selected public consumer implementations.

## QRK Studio

Both controls already use shared components and the `sm` size. The sidebar's Page controls uses the Radix-backed `SelectTrigger`, with local overrides for smaller semibold text, reduced padding, and a borderless surface. Publish Site uses the shared `Button` through a Radix dialog trigger. The button supplies medium-weight text and its standard padding. [Sidebar controls](../../apps/app/app/%5Busername%5D/site/%5BsiteId%5D/page/%5BpageId%5D/%28drawer%29/layout.tsx#L157-L190), [Publish dialog trigger](../../apps/app/app/%5Busername%5D/site/%5BsiteId%5D/page/%5BpageId%5D/%28drawer%29/PublishSiteDialog.tsx#L107-L111), [SelectTrigger](../../apps/app/components/ui/select.tsx#L21-L42), [Button](../../apps/app/components/ui/button.tsx#L7-L26).

On the annotated local desktop page, Chromium measured both controls at 32 px high, 10 px from the top, with an 8 px corner radius and 6 px gap. Page controls measured 12 px text at weight 600 and 6 px inline-start padding. Publish Site measured 14 px text at weight 500 and 12 px inline-start padding. The visible boxes were about 119 px and 128 px wide with the **Edit brick** and **Publish Site** labels respectively. The width measurements apply to this label pair. Page controls can also display **Page settings** and **Site settings**.

## Referenced shadcn editor

The reference's **Menu** and **Export** use matching 28 px heights, 8 px horizontal padding, 8 px radii, 12 px text at weight 500, 4 px gaps, and 14 px chevrons. Their widths follow their labels. Both render as dropdown-menu triggers. Menu takes its light gray fill from the input theme token and Export takes its near-black fill from the primary token. This is an observed rendering of the supplied example. [Live shadcn editor](https://ds.shadcn.com/examples/editor).

## How the shadcn docs site uses its own components

The docs app imports generated preset components alongside its hand-authored New York v4 registry. The build combines authored primitive registries such as Radix and Base UI with style CSS and emits both local `styles/<base-style>/ui/*` modules for the site and installable registry JSON under `public/r/`. New York v4 remains a separate source registry. [Registry source and outputs](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/README.md#source-of-truth-authored-by-hand), [registry build](https://github.com/shadcn-ui/ui/blob/main/apps/v4/scripts/build-registry.mts#L25-L69).

- **New** imports the generated Radix Nova Button. The header uses `asChild` to style the link to `/create`, requests `sm`, and applies its own 31 px height and large-radius utility. [Site header](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/site-header.tsx#L12-L51).
- **Search documentation** composes the New York v4 Button with a Radix dialog trigger using `asChild`. The trigger keeps the outline variant and sets a muted fill, `h-8`, `rounded-lg`, and responsive widths. [Command menu imports](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/command-menu.tsx#L17-L35), [search trigger](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/command-menu.tsx#L400-L414).
- **Mobile Menu** uses a New York v4 ghost Button as the popover trigger via `asChild`. It sets `h-8` and extends the touch target. The **theme toggle** uses the same registry's icon Button and sets `size-8` with the same touch-target utility. [Mobile nav](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/mobile-nav.tsx#L74-L106), [theme toggle](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/mode-switcher.tsx#L7-L34).

The app layout mounts that header for the docs. The nested docs layout imports the New York v4 `SidebarProvider` directly and sets a docs-specific sidebar width and responsive grid. [App layout](https://github.com/shadcn-ui/ui/blob/main/apps/v4/app/%28app%29/layout.tsx), [docs layout](https://github.com/shadcn-ui/ui/blob/main/apps/v4/app/%28app%29/docs/layout.tsx).

## How shadcn and consumers compose controls

- **shadcn/ui** distributes component source for local ownership. The Nova preset gives `Button` and `SelectTrigger` matching heights at the default and small sizes, with component-specific padding and typography. The dashboard demo places a small view select and small action buttons in one responsive toolbar. Its Customize Columns menu uses the same shared Button as Add Section by composing the Radix trigger with `asChild`. [shadcn introduction](https://ui.shadcn.com/docs), [component index](https://ui.shadcn.com/docs/components), [Radix Button](https://ui.shadcn.com/docs/components/radix/button), [Radix Select](https://ui.shadcn.com/docs/components/radix/select), [Nova button sizes](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/styles/style-nova.css#L134-L172), [Nova select sizing](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/styles/style-nova.css#L903-L917), [dashboard toolbar](https://github.com/shadcn-ui/ui/blob/main/apps/v4/app/%28app%29/examples/dashboard/components/data-table.tsx).
- **OpenStatus** matches its shared Button and SelectTrigger at `h-9` by default and `h-8` at `sm`. Its dashboard property inspector goes further where visual alignment repeats. One local class recipe supplies the height, horizontal padding, and surface treatment for the select, menu, and date/time controls, while each retains its own behavior. [shadcn configuration](https://github.com/openstatusHQ/openstatus/blob/main/packages/ui/components.json), [Button](https://github.com/openstatusHQ/openstatus/blob/main/packages/ui/src/components/ui/button.tsx#L20-L32), [SelectTrigger](https://github.com/openstatusHQ/openstatus/blob/main/packages/ui/src/components/ui/select.tsx#L24-L45), [dashboard property controls](https://github.com/openstatusHQ/openstatus/blob/36288495c8544d4498986be7d72c37ee7e666837/apps/dashboard/src/components/content/property-list.tsx#L100-L171).
- **Supabase Studio** composes an action and a format dropdown in the schema graph. The dropdown trigger uses `asChild` with a shared `Button`. It uses the same `tiny` size as the adjacent Copy as SQL action and adjusts the adjoining corners to form a split control. This example demonstrates using one Button recipe when both controls are actions in the same group. [Supabase UI package](https://github.com/supabase/supabase/blob/master/packages/ui/README.md), [schema graph controls](https://github.com/supabase/supabase/blob/master/apps/studio/components/interfaces/Database/Schemas/SchemaGraph.tsx).

## Implication for QRK

For the referenced look, use the same compact dimensions and typography for both sidebar controls, with a light neutral fill for Page controls and the primary fill for Publish Site. Keep the existing select and dialog semantics, including the Page controls chevron. Let widths follow labels and verify that the longer choices still fit beside Publish Site and Close. If retaining QRK's 32 px height, bring the Page controls text weight, size, and padding into line with the neighboring `sm` Button. In either case, use the current component owners and consider sharing a visual recipe when the same alignment repeats elsewhere.
