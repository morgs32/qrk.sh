# shadcn Base UI patterns in Brick inputs

Checked 2026-11-11 against current Bricks source and official shadcn Base UI docs, registry source, and Base UI and WAI-ARIA guidance. Scope is the Form Inputs catalog and the Brick sidebar forms it represents. The earlier [input group focus audit](./shadcn-input-group-focus.md) covers icon placement, steppers, and focus rings. Source review only.

## Interaction gaps

1. **Map Place implements its own asynchronous combobox.** Arrow keys update a visual index while DOM focus stays on the input. The input never sets `aria-activedescendant` to the active option. Popup and option IDs are also fixed strings, so multiple mounted instances could collide. shadcn's Base UI Combobox owns the input, list, and items. Base UI's async single-select example supports remote result windows and stable IDs while retaining the selected item. Keep Google search, place details, selection, attribution, and save behavior in the Brick. Use the primitive for combobox interaction and focus. [GooglePlaceLookup](../../apps/bricks/src/mapPlace/react/GooglePlaceLookup.tsx), [shadcn Combobox](https://ui.shadcn.com/docs/components/base/combobox#composition), [Base UI async search](https://base-ui.com/react/components/combobox#async-search-single), [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/#wai-aria-roles-states-and-properties)
2. **Material Symbols search declares a listbox over ordinary buttons.** Each result is an independently tabbable button with `role="option"`; the results have no arrow-key navigation or active option management. The grid and pagination are valid product choices. Keep those while choosing either ordinary named result buttons with an exposed selection state or a selection primitive that provides the composite keyboard behavior. A plain search input followed by buttons remains a viable layout for this persistent results grid. [MaterialSymbolsIconLookup](../../apps/bricks/src/swatchAndIcon/react/MaterialSymbolsIconLookup.tsx), [WAI-ARIA listbox keyboard interaction](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/#keyboard-interaction), [shadcn Combobox](https://ui.shadcn.com/docs/components/base/combobox)
3. **Align mixes radio roles with toggle primitives.** `ButtonGroupInput` uses Base UI `ToggleGroup` and `Toggle`, overrides their roles to `radiogroup` and `radio`, and rejects deselection when the toggle callback returns no value. For an exclusive form value, shadcn's Base UI Radio Group fits directly and can keep the icon segment styling. A true Toggle Group fits toolbar toggle actions with pressed state. [ButtonGroupInput](../../apps/bricks/src/react/ButtonGroupInput.tsx), [shadcn Radio Group](https://ui.shadcn.com/docs/components/base/radio-group), [shadcn Toggle Group](https://ui.shadcn.com/docs/components/base/toggle-group), [Base UI Toggle Group](https://base-ui.com/react/components/toggle-group)
4. **Shadow silently rejects malformed values.** Its shorthand field leaves an invalid draft visible without explanation when blur rejects the component count, nonfinite values, or negative blur. The shorthand and detailed editor are domain behavior. The shared field pattern already provides an inline error, `aria-invalid`, and an associated description for analogous text validation. [ShadowInput](../../apps/bricks/src/react/ShadowInput.tsx), [shadcn Field validation](https://ui.shadcn.com/docs/components/base/field#validation-and-errors)

## Component and styling differences

1. **Fit already uses Base UI Select.** `DropdownInput` assembles the standard trigger, value, portal, list, item and indicator primitives with its own classes and label wrapper. Its edge alignment is a documented option. The delta is the shared Field and Select styling, including the official registry's optional popup affordances, rather than selection mechanics. [DropdownInput](../../apps/bricks/src/react/DropdownInput.tsx), [shadcn Select](https://ui.shadcn.com/docs/components/base/select#align-item-with-trigger), [Base UI Select registry source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/ui/select.tsx)
2. **Image Zoom is a native range input.** It is labeled and lives in a shared Field. shadcn provides a Base UI Slider for a styled track and thumb. The surrounding editor already uses Base UI Dialog and Tabs directly; its shells use local styles. Upload, URL entry, crop state, and Apply are the QRK workflow. The file field already follows shadcn's documented `type="file"` pattern. [ImageUploadInput](../../apps/bricks/src/react/ImageUploadInput.tsx), [shadcn Slider](https://ui.shadcn.com/docs/components/base/slider), [Dialog](https://ui.shadcn.com/docs/components/base/dialog#composition), [Tabs](https://ui.shadcn.com/docs/components/base/tabs#composition), [File input](https://ui.shadcn.com/docs/components/base/input#file)
3. **Color, Border, Shadow and Radius use domain-specific editor combinations.** Color combines a hex text field with a `react-colorful` picker; Border adds a width, Shadow adds four dimensions, and Radius adds mixed-value and per-corner editing. The registry component index does not list a drop-in for these editors. Radius and the shared swatch picker already use Base UI Popover for behavior, with custom panel styling and an explicitly labeled popup. The shadcn Popover shell and Field/Input Group styling can be shared while keeping the picker and property models. [ColorInput](../../apps/bricks/src/react/ColorInput.tsx), [BorderInput](../../apps/bricks/src/react/BorderInput.tsx), [ShadowInput](../../apps/bricks/src/react/ShadowInput.tsx), [RadiusInput](../../apps/bricks/src/react/RadiusInput.tsx), [SwatchPopover](../../apps/bricks/src/react/SwatchPopover.tsx), [shadcn component index](https://ui.shadcn.com/docs/components), [shadcn Popover](https://ui.shadcn.com/docs/components/base/popover)
4. **Position and Size are named numeric groups.** Each uses a named group with individually labeled Base UI Number Fields. Their paired controls and prefixes are a QRK composition; the shared numeric input focus fix applies per value. The label grid and 28px controls are compact Studio styling. [PositionInput](../../apps/bricks/src/react/PositionInput.tsx), [SizeInput](../../apps/bricks/src/react/SizeInput.tsx), [Base UI Number Field](https://base-ui.com/react/components/number-field)
5. **Ordinary text, URL, search and file fields already follow the adapted Field composition.** They use a native input, associated label, control column, and associated description/error when provided. Bricks implements horizontal and vertical orientations with a fixed compact label column instead of the registry's flex-based and responsive variants. Provider-specific autosave remains application behavior. [TextInput](../../apps/bricks/src/react/TextInput.tsx), [Field implementation](../../apps/bricks/src/react/field.tsx), [Form Inputs catalog](../../apps/bricks/src/react/FormInputs.stories.tsx), [shadcn Input](https://ui.shadcn.com/docs/components/base/input), [shadcn Field](https://ui.shadcn.com/docs/components/base/field#responsive-layout)

Map Place and Material Symbols are used by Brick sidebar forms. Align, Fit, Position, Size, Radius, Border, and Shadow are only mounted by the Form Inputs catalog in the current `apps/` TSX usage scan. Prioritize the two live lookup interaction gaps ahead of catalog-only component and styling differences.
