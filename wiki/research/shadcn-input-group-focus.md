# Focus rings for grouped Brick inputs

## shadcn Base UI behavior

- **The group draws the ring.** shadcn’s Nova style puts the border and three-pixel focus ring on `InputGroup` when its `data-slot="input-group-control"` descendant matches `:focus-visible`. The nested input suppresses its own focus and invalid rings. The outer ring surrounds the input and any addons inside the group. Nova also places the invalid state on the group. [Nova Input Group CSS](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/styles/style-nova.css#L1260-L1306)
- **Icons and buttons have different focus behavior.** Addons can render at either end of the input. shadcn recommends placing addons after the input in DOM order and using alignment for their visual placement. Clicking non-button addon content focuses the input. `InputGroupButton` uses the normal button, whose own focus-visible style identifies it when focused. A focused addon button alone does not match the group’s input-specific selector. [Input Group docs](https://ui.shadcn.com/docs/components/base/input-group#inputgroupaddon), [Base UI registry source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/ui/input-group.tsx#L22-L119), [Nova Button CSS](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/styles/style-nova.css#L134-L136)

## Applying it to Stack height

- Bricks’ `NumberField.Group` already wraps the prefix or icon, input, steppers, and optional trailing control. Its nested `Input` currently draws the ring, which explains the narrower outline. The existing App `InputGroup` shows the group-owned pattern. [NumberInput](../../apps/bricks/src/react/NumberInput.tsx), [Bricks Input](../../apps/bricks/src/react/Input.tsx), [App InputGroup](../../apps/app/components/ui/input-group.tsx)
- Put the input-focus ring on the existing number group and suppress the nested input’s ring there. Preserve Base UI’s stepper behavior. Its buttons have `tabIndex={-1}` because keyboard users change values through the numeric input, and non-touch presses focus the input. Keep a distinct focus indicator for any independently tabbable trailing action. The decorative icon in `TextInput` already overlays a full-width input, so its current input ring encloses the icon. [Base UI Number Field anatomy](https://base-ui.com/react/components/number-field#anatomy), [Base UI stepper source](https://github.com/mui/base-ui/blob/master/packages/react/src/number-field/root/useNumberFieldButton.ts), [TextInput](../../apps/bricks/src/react/TextInput.tsx)

## Do the current Brick controls follow the pattern?

- **Decorative icons follow the visual intent.** Figma's link icon uses the shared `TextInput` overlay, with `aria-hidden` and pointer events disabled. Place and icon searches use their own overlays. Number inputs put prefixes and icons before the input in the DOM. These paths use custom positioning instead of shadcn's input-first DOM order and aligned addons. With an overlay, the pointer reaches the underlying input; shadcn forwards a click on non-button addon content to the input. [TextInput](../../apps/bricks/src/react/TextInput.tsx), [GooglePlaceLookup](../../apps/bricks/src/mapPlace/react/GooglePlaceLookup.tsx), [MaterialSymbolsIconLookup](../../apps/bricks/src/swatchAndIcon/react/MaterialSymbolsIconLookup.tsx), [NumberInput](../../apps/bricks/src/react/NumberInput.tsx), [shadcn Input Group alignment](https://ui.shadcn.com/docs/components/base/input-group#align), [shadcn addon source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/ui/input-group.tsx#L44-L60)
- **Numeric steppers use Base UI's Number Field.** The official shadcn component index lists Input Group and has no Number Field entry. QRK uses `NumberField.Increment` and `NumberField.Decrement` with compact local buttons inside `NumberField.Group`. This keeps Base UI's increment/decrement behavior, including arrow keys on the input and steppers outside the sequential Tab order. The visual mismatch is the inner input ring. [shadcn component index](https://ui.shadcn.com/docs/components#all-components), [Base UI Number Field](https://base-ui.com/react/components/number-field#anatomy), [Base UI stepper source](https://github.com/mui/base-ui/blob/master/packages/react/src/number-field/root/useNumberFieldButton.ts), [NumberInput](../../apps/bricks/src/react/NumberInput.tsx)
- **Tabbable actions are separate from steppers.** The color swatches in Border, Shadow, and Color sit after the input inside their control and use an accessible Base UI popover trigger rendered as a named Bricks ghost button. They retain their own button focus ring, matching shadcn's keyboard intent with custom grouping. Map Place's clear action is a named native button overlaid after the field and relies on the browser's focus styling. The Border, Shadow, and Color clear buttons and the Radius details trigger sit outside their input surfaces and keep their own focus styles. QRK's shadcn-style `InputGroup` currently lives in App. Bricks composes these controls locally.
