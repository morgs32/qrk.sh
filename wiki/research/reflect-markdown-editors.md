# Reflect's Markdown editor and alternatives to Tiptap

Researched 2026-10-13. Static source and official-documentation review; no editor integration, migration, or runtime comparison was performed. Reflect is pinned to [`b094504`](https://github.com/team-reflect/reflect-open/tree/b094504cd24746e8b2e2572b4d1c869481804f74); Meowdown is pinned to [`55940d3`](https://github.com/prosekit/meowdown/tree/55940d37847e12f8c1a8b83a2d468436fc9b6e55). These Meowdown source packages have the same versions as Reflect's resolved dependencies: core `0.81.1`, React `0.80.2`, Markdown `0.77.0`. See the [Reflect lockfile](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/pnpm-lock.yaml#L1269-L1279) and Meowdown's [core](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/package.json#L1-L9), [React](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/react/package.json#L1-L9), and [Markdown](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/markdown/package.json#L1-L9) manifests.

## What Reflect actually uses

Reflect mounts **Meowdown's `<MarkdownEditor>`**, imported from `@meowdown/react`. Its `NoteEditor` wrapper supplies initial Markdown, syntax visibility mode, app navigation, attachment persistence, autocomplete, and other host callbacks. The underlying engine uses ProseKit/ProseMirror; it is a separate reusable library, rather than an editor implemented only inside Reflect. Sources: [Reflect imports and wrapper contract](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L26-L66), [actual component and callbacks](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L445-L507), [Meowdown engine dependencies](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/package.json#L33-L47).

The useful distinction is **how Meowdown represents inline Markdown**. Its Markdown parser creates ProseMirror block nodes, while inline punctuation remains literal text. Emphasis, links, and inline code are subsequently styled by marks over that text. Saving reads the text back; the marks do not regenerate the inline delimiters. Sources: [Markdown-to-document converter](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/md-to-pm.ts#L23-L41), [inline-mark update pipeline](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/extensions/inline-mark-plugin.ts#L3-L16), [document-to-AST conversion](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/pm-to-ast.ts#L21-L24), [text extraction](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/pm-to-ast.ts#L104-L120).

For `**bold**`, the following is a conceptual illustration of the resulting inline runs, not its public API:

```text
paragraph
  "**"    mdPack + mdStrong + mdMark   // literal opening punctuation
  "bold"  mdPack + mdStrong            // displayed as strong text
  "**"    mdPack + mdStrong + mdMark   // literal closing punctuation
```

The library's test explicitly checks the body and punctuation marks. `mdStrong` renders a `<strong>` element; `mdMark` renders a syntax span. Sources: [bold representation test](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/extensions/inline-mark-plugin.test.tsx#L20-L31), [mark definitions](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/extensions/inline-marks.ts#L65-L91).

This still has a block schema and a serializer. Headings, lists, fences, and tables become structured nodes; choices such as list marker, heading closing hashes, and fence length are retained as attributes. It is therefore more precise to call it **Markdown-preserving inline editing within a structured block editor** than a flat source-text editor. Sources: [AST-to-ProseMirror conversion](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/ast-to-pm.ts#L14-L63), [serialization entry point](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/pm-to-md.ts#L16-L20).

## How syntax disappears and reappears

Reflect offers Hide, Hybrid, and Show. Hybrid maps to Meowdown's `focus` mode. These modes change visibility within the same editor; Reflect's settings describe Hybrid as showing syntax around the cursor. Sources: [setting choices](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/components/settings/editor-section.tsx#L17-L33), [mode mapping](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/mark-mode.ts#L4-L18), [mode forwarded to editor](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L445-L454).

There is no separate `raw` mode in this API: even `show` mounts the same `ProseKitEditor`, with a different `markMode`. Meowdown's own component defaults to `focus`; Reflect's wrapper default is `hide` when its caller omits the mode. Sources: [shared rendering path](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/react/src/components/editor.tsx#L573-L583), [Meowdown default](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/react/src/components/editor.tsx#L426-L428), [Reflect wrapper default](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L256-L261).

In `focus` mode, the selection identifies the inline units it touches, and ProseMirror inline decorations add a `.show` class across those units. CSS normally collapses syntax spans with `font-size: 0` and `opacity: 0`, then restores them for `.show`. The `**` characters remain in the document throughout. `show` keeps punctuation visible; `hide` suppresses ordinary syntax. Sources: [mode and selection-decoration implementation](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/extensions/mark-mode.ts#L10-L98), [visibility CSS](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/style.css#L803-L833).

Meowdown's dialect builds on Lezer Markdown with GFM and adds wiki links/embeds, hashtags, highlights, math, and additional autolinks. Reflect connects note and asset behavior through resolvers and event handlers rather than owning all of that parsing. Sources: [parser configuration](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/markdown/src/parser.ts#L25-L41), [Reflect integration callbacks](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L476-L497).

## Markdown persistence and fidelity

Reflect's editor reads initial Markdown once. On user document changes, Reflect calls `getMarkdown()` and passes the result to its document session; programmatic replacements are silent to avoid save loops. The session keeps frontmatter outside the editor and writes header plus Markdown body to the note file. Sources: [uncontrolled editor contract](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L62-L85), [change callback](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/note-editor.tsx#L354-L356), [session buffers](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/packages/core/src/documents/note-session-service.ts#L94-L106), [file write](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/packages/core/src/documents/note-session-service.ts#L242-L268).

This is not a blanket byte-preservation guarantee. Meowdown classifies round trips as `exact`, `normalizing`, or `lossy`; even `exact` permits trailing-newline differences. Reflect protects a loaded note from editing when its body is classified `lossy`, and separately protects conflict markers. Its own tests acknowledge that loose lists can normalize. Sources: [classifier definition and implementation](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/markdown/src/ast/check-roundtrip.ts#L6-L81), [Reflect load protection](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/packages/core/src/documents/note-session-service.ts#L447-L459), [round-trip examples](https://github.com/team-reflect/reflect-open/blob/b094504cd24746e8b2e2572b4d1c869481804f74/apps/desktop/src/editor/roundtrip.test.ts#L4-L23).

## Alternatives and the Tiptap baseline

“Markdown-centric” can mean literal source editing, live preview over retained syntax, or a rich editor with Markdown import/export. Those are different requirements. The following judgments concern architecture and documented capabilities, not measured editing quality.

| Option | Verified model and interface | Assessment for this question |
| --- | --- | --- |
| **Meowdown** | ProseKit/ProseMirror block tree, retained inline syntax, hide/focus/show, React component; MIT. Sources: [converter](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/converters/md-to-pm.ts#L23-L41), [modes](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/core/src/extensions/mark-mode.ts#L10-L18), [React API](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/packages/react/src/components/editor.tsx#L58-L85), [license](https://github.com/prosekit/meowdown/blob/55940d37847e12f8c1a8b83a2d468436fc9b6e55/LICENSE). | First candidate when the desired behavior is Reflect-style editing. The inline representation is the distinguishing feature. |
| **CodeMirror 6** | Flat text document; transactions replace text ranges. Markdown language support and mark/widget/replacement decorations are available. Sources: [data model](https://codemirror.net/docs/guide/#data-model), [Markdown API](https://codemirror.net/docs/ref/#lang-markdown), [decoration examples](https://codemirror.net/examples/decoration/). | Best architectural fit when source text is primary and avoiding rich-schema conversion matters most. A polished live-preview experience requires assembling additional behavior. |
| **Milkdown / Crepe** | Markdown ↔ remark AST ↔ ProseMirror transformations. Crepe packages features including toolbar, slash menu, images, and tables; an official React recipe exists. Sources: [transformer](https://milkdown.dev/docs/api/transformer), [Crepe](https://milkdown.dev/docs/api/crepe), [React](https://milkdown.dev/docs/recipes/react), [MIT license](https://github.com/Milkdown/milkdown/blob/main/LICENSE). | Markdown-focused rich-editor framework with a packaged starting point. It retains semantic schema conversion, so should not be chosen on an assumption that original source spelling is preserved. |
| **MDXEditor** | React component; Lexical ↔ MDAST visitors implement Markdown import/export. `markdown`, `onChange`, imperative Markdown methods, and a source/diff plugin are documented. Sources: [architecture](https://mdxeditor.dev/editor/docs/overview), [API usage](https://mdxeditor.dev/editor/docs/getting-started), [source/diff](https://mdxeditor.dev/editor/docs/diff-source), [MIT license](https://github.com/mdx-editor/editor/blob/main/LICENSE). | Useful for a packaged React rich editor with an explicit source view. Unsupported syntax requires corresponding plugins or conversion handling; it is not an arbitrary-source-preserving editor. See [error handling](https://mdxeditor.dev/editor/docs/error-handling). |
| **Tiptap with Markdown extension** | Official Markdown support exists and is labeled Beta. MarkedJS and extension handlers convert Markdown to Tiptap JSON, and the extension serializes back; `contentType: 'markdown'` and `getMarkdown()` are documented. Sources: [Markdown architecture/status](https://tiptap.dev/docs/editor/markdown), [basic usage](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage), [editor API](https://tiptap.dev/docs/editor/markdown/api/editor). | Staying with Tiptap is reasonable if Markdown I/O is the requirement. That does not provide Meowdown's retained-literal-inline-syntax model by itself. |

CodeMirror's replacement decorations can hide source ranges without replacing document text, which supplies a building block for live preview. It avoids a mandatory Markdown → semantic rich schema → Markdown round trip, but that is an architectural property, not a guarantee that every wrapper preserves bytes, line separators, and paste behavior. Sources: [replacement decorations](https://codemirror.net/examples/decoration/), [document extraction](https://codemirror.net/docs/migration/#getting-the-document-and-selection).

## Recommendation

For the behavior shown by Reflect, evaluate **Meowdown first**. For an editor whose actual document must remain a plain text buffer, evaluate **CodeMirror 6**. Choose **Milkdown/Crepe** or **MDXEditor** when the priority is their packaged rich-editing experience and Markdown as the persistence/interchange format. Keep Tiptap in consideration if Markdown import/export already solves the requirement.

Before choosing, compare actual required documents: nested lists, noncanonical markers, tables, raw HTML, wiki links, incomplete syntax, pasted content, and mobile selection. This is a proposed evaluation checklist, not a claim that any candidate passes or fails those cases.
